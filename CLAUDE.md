# CLAUDE.md

Источник истины по проекту — `tech.md` в корне репозитория. Прочитать его перед началом любой работы и подчиняться ему дословно: стек, схема БД, контракт ИИ-тренера, структура папок, правила кода, тесты, Definition of Done.

Правила для этой сессии:

- Контракты (схема БД, типы, формат ответа DeepSeek) не выдумывать. Не хватает контракта — остановиться и зафиксировать блок `CONTRACT GAP` в конце `tech.md` (раздел «Процесс работы с пробелами в контракте»), не писать код с придуманным типом.
- Новая фича повторяет структуру эталонной вертикали `routes/(app)/trainer` (домен → репозиторий → сервис → `load`/`actions`/`+server.ts` → страница → локальные компоненты), а не изобретает свою раскладку.
- Одна задача за сессию = один вертикальный слайс. Не вываливать сразу всё приложение — сфокусированный дифф.
- Любое изменение `tech.md` (новый контракт, поле схемы) — append-only, с бампом версии сверху файла.
- Перед коммитом: `svelte-check`, `eslint`/`prettier`, `vitest`, `build` — все зелёные (Definition of Done из `tech.md`, раздел 13).
- Коммиты — Conventional Commits, английский язык, маленькими логическими шагами по ходу работы.
- Тесты — из критериев приёмки задачи, не зеркало реализации (доктрина в `tech.md`, раздел 10).
